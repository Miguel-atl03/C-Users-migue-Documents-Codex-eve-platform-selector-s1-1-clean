Este chip guía la redacción de responsabilidades y actividades en WorkMap para que el usuario describa su rol funcional con lenguaje operativo, verificable y útil para las fases posteriores de EVE.

La ayuda debe permitir que el usuario distinga:

- Responsabilidades: el poder de decidir, regular, validar o responder por un criterio.
- Actividades: el hacer concreto que transforma un insumo, documento, información, material, solicitud o decisión en una salida útil.
- Áreas: los espacios organizacionales donde el trabajo participa realmente, aunque no coincidan con el departamento formal.

## 4. Responsabilidades

### Definición

Bajo la metodología de Raúl Espejo/Viplan, una responsabilidad no es una tarea. Es una declaración de discrecionalidad: expresa sobre qué variable, recurso, criterio o límite una persona tiene permiso real para decidir, regular, validar o rendir cuentas.

La responsabilidad describe el "ser" del rol: aquello por lo que la persona responde y donde tiene margen de acción verificable.

### Fórmula Espejo

Una responsabilidad sistémicamente válida debe seguir esta estructura:

`[Verbo de Acción Verificable] + [Objeto de Discrecionalidad] + [Contexto de Regulación] + [Restricción]`

Componentes:

- **Verbo de Acción Verificable:** acción que permite verificar si la responsabilidad se ejerció o no.
- **Objeto de Discrecionalidad:** recurso, variable o ámbito sobre el cual la persona tiene permiso de decidir.
- **Contexto de Regulación:** propósito cibernético o situación donde esa responsabilidad absorbe variedad.
- **Restricción:** límite, regla, margen, criterio o condición que contiene la autonomía.

### Verbos de poder

Usar verbos que expresen decisión, criterio, autoridad o accountability:

- Define.
- Aprueba.
- Regula.
- Ajusta.
- Verifica.
- Informa.
- Ejecuta.
- Autoriza.
- Decide.
- Prioriza.
- Valida.
- Establece.
- Asigna.
- Libera.
- Escala.
- Evalúa.
- Audita.
- Sincroniza.
- Negocia.

### Verbos débiles a evitar

Evitar verbos que diluyen la responsabilidad o no dejan claro quién tiene la última palabra:

- Apoyar.
- Ayudar.
- Gestionar.
- Ver.
- Participar.

Estos verbos pueden ocultar la discrecionalidad real, fragmentar la rendición de cuentas y provocar microgerencia.

### Ejemplos mal/bien

Área de producción:

- Mal: "Hacer el programa de producción de la semana."
- Bien: "Define el programa de producción semanal para absorber la variedad de pedidos pendientes, asegurando que no se supere la capacidad instalada del Sistema 1."

Área de ventas:

- Mal: "Visitar clientes y reportar las ventas."
- Bien: "Regula la asignación de descuentos comerciales dentro del margen del 10% para asegurar el cierre de ventas frente a la competencia local sin comprometer la rentabilidad acordada con S3."

Área de recursos humanos:

- Mal: "Ayudar en el proceso de contratación."
- Bien: "Verifica la alineación de los candidatos con los perfiles de competencia definidos y aprueba su ingreso para garantizar la capacidad operativa de las unidades primarias."

### Explicación sistémica

Una responsabilidad ambigua rompe la viabilidad porque no define quién tiene la última palabra sobre un recurso o criterio. Si todos "apoyan", nadie puede ser auditado con claridad. El sistema termina centralizando las decisiones en el jefe, aumenta la microgerencia y reduce la capacidad de absorber variedad.

Redactar con la Fórmula Espejo distribuye la discrecionalidad de forma precisa y hace viable la rendición de cuentas.

### Lateral visible para usuario

Texto rector para ayuda lateral:

> Una responsabilidad es algo de tu rol donde respondes por una decisión, criterio, validación, autorización, prioridad o límite. No es una tarea suelta; es aquello sobre lo que tienes discreción y por lo que puedes rendir cuentas.

Estructura visible:

`Yo + verbo de decisión + sobre qué respondo + para qué sirve o cuál es el límite.`

Ejemplo visible:

`Yo autorizo descuentos comerciales dentro del margen permitido para cerrar ventas sin afectar la rentabilidad.`

## 5. Actividades

### Definición

Una actividad es una transformación física o informacional. Si la responsabilidad expresa el poder de decidir, la actividad expresa el hacer concreto que transforma algo.

En Viplan, las actividades pertenecen al proceso de implementación del Sistema 1. Una actividad mal redactada produce ruido, retrabajo y procesos fracturados.

### Fórmula de Transformación

Una actividad debe seguir esta estructura:

`[Verbo de Acción Operativa] + [Insumo / Objeto] + [Procedimiento / Estándar] + [Producto / Salida]`

Componentes:

- **Verbo de Acción Operativa:** acción concreta que transforma algo.
- **Insumo / Objeto:** aquello que entra al proceso o sobre lo que se trabaja.
- **Procedimiento / Estándar:** cómo se hace, con qué regla, protocolo, sistema, fórmula o criterio.
- **Producto / Salida:** resultado tangible o informacional que queda listo para el siguiente paso o para el cliente.

### Verbos operativos

Usar verbos que describan una acción concreta:

- Reviso.
- Registro.
- Actualizo.
- Capturo.
- Calculo.
- Concilio.
- Comparo.
- Mido.
- Clasifico.
- Tipifico.
- Envío.
- Entrego.
- Preparo.
- Documento.
- Cargo.
- Organizo.
- Notifico.
- Cierro.
- Empaco.
- Ensamblo.
- Traduzco.
- Digito.
- Sueldo.
- Listo.

### Diferencia contra responsabilidades

| Actividad | Responsabilidad |
| --- | --- |
| Hacer. | Decidir o responder. |
| Transforma insumos. | Regula variedad. |
| Describe el paso operativo. | Describe el criterio o autoridad. |
| Usa verbos como registrar, medir, tipificar, enviar. | Usa verbos como definir, aprobar, auditar, autorizar, regular. |

### Ejemplos mal/bien

Contabilidad:

- Responsabilidad: "Define el catálogo de cuentas para asegurar la integridad de la información financiera."
- Actividad: "Registra las facturas de proveedores en el ERP siguiendo el catálogo de cuentas para generar el asiento contable de gasto."

Control de calidad:

- Responsabilidad: "Aprueba los estándares de tolerancia técnica para los productos terminados."
- Actividad: "Mide las dimensiones de la pieza producida utilizando el calibrador digital para verificar si cumple con la tolerancia aprobada."

Servicio al cliente:

- Responsabilidad: "Regula el protocolo de atención ante quejas críticas para proteger la imagen de marca."
- Actividad: "Tipifica el reclamo del cliente en la plataforma CRM siguiendo el protocolo de atención para iniciar el flujo de resolución."

### Explicación sistémica

Si una actividad no especifica qué insumo entra ni qué producto sale, el Sistema 1 no puede medir su propia eficiencia. El trabajador no sabe cuándo terminó con éxito, aparece variedad espuria y el jefe debe intervenir para unir puntos que el proceso debería haber conectado.

La responsabilidad da permiso para decidir. La actividad da método para transformar. Sin ambas claras, la viabilidad queda debilitada.

### Lateral visible para usuario

Texto rector para ayuda lateral:

> Una actividad es una acción concreta que realizas para transformar información, documentos, solicitudes, materiales o decisiones en algo útil para el siguiente paso. Ayuda a entender qué haces y qué queda hecho al terminar.

Estructura visible:

`Acción concreta + sobre qué trabajo + cómo lo hago o qué dejo listo.`

Ejemplo visible:

`Registro facturas de proveedores en el ERP para dejar listo el asiento contable.`

## 6. Ubicación de área

El usuario debe seleccionar las áreas donde su trabajo participa realmente, aunque no sean el nombre exacto de su puesto o departamento formal.

Reglas:

- Elegir áreas donde el trabajo participa de forma real.
- No elegir solo el departamento donde la persona está contratada.
- Incluir áreas donde el trabajo impacta.
- Incluir áreas donde el trabajo alimenta información.
- Incluir áreas donde el trabajo coordina.
- Incluir áreas donde el trabajo entrega algo.
- Incluir áreas donde el trabajo desbloquea trabajo para otros.
- Si el área no aparece, usar "Otra área" y escribir un nombre corto y claro.

Idea guía:

`Yo participo en [área] cuando mi trabajo ayuda a [resultado, proceso o entrega].`
