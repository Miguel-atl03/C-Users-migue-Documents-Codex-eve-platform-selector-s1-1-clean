1. Decisión arquitectónica del catálogo runtime
El nuevo catálogo no es una lista recortada de preguntas. Es una capa runtime compuesta por interacciones visibles, confirmaciones asistidas, derivaciones internas, reglas de branching, gaps y salidas estructurales hacia MMABP. La unidad operativa visible se denomina Pregunta Runtime Compuesta y puede mapear a uno o varios Nodos Canónicos de Captura del Catálogo Madre.
Capa
Regla
Catálogo Madre
Se conserva intacto: 164 nodos con códigos fuente, rutas críticas, variables, gobierno epistemológico y mapeo MMABP.
Catálogo Runtime 40+20
Se derivan 40 interacciones base y 20 causales máximas por actividad. La experiencia visible se reduce sin destruir trazabilidad.
Mapa MMABP
Cada interacción alimenta PM, MoC, PF, OLC, conformance, consistencia o readiness. Si no protege un elemento estructural, no se vuelve visible por defecto.
Producción Paralela
Consume candidatos estructurales y variables canónicas cerradas; no infiere desde texto libre ni diagnostica.
B7
Permanece como verificación ligera y frontera no diagnóstica; sus preguntas son microconfirmaciones gobernadas, no bloque diagnóstico.
Regla clínica: la reducción visible solo es válida si preserva la capacidad de dibujar PM, MoC, PF y OLC con conformance individual y consistencia cruzada. La experiencia del usuario no debe mejorar a costa de ceguera arquitectónica.

4. Reglas de branching y apertura causal
La apertura causal se gobierna por señales estructurales. El motor no debe profundizar para completar un formulario, sino para cerrar rutas canónicas, proteger conformance, evitar contradicciones MMABP o preservar readiness hacia Producción Paralela.

Condición
Causal

Si WorkMapIntake llega incompleto, activar reconstrucción guiada; no convertir inferencia IA en evidencia dura sin confirmación.

Regla B1
Si el disparador es ambiguo, contradictorio o ausente cuando debería ocurrir, abrir excepción/jerarquía de fuente.

Regla B2
Si hay múltiples dimensiones o la capacidad no puede medirse, abrir dimensión dominante. Si hay falla, abrir 2.10/B2.B.

Anexo C. Reglas de no pérdida del Catálogo Madre
Regla
Aplicación
No eliminación
Ningún nodo del Catálogo Madre se borra. Los nodos no visibles permanecen como internos, aclaratorios, derivables, gaps o preparación no diagnóstica.
No síntesis destructiva
Una interacción visible compuesta puede agrupar varios nodos, pero sus variables deben persistir separadas.
No inferencia dura
Una inferencia IA no confirmada no entra como captured_user_evidence.
No diagnóstico temprano
Capa 1 no diagnostica VSM/AHE ni produce patología final.
No diagramación desde texto crudo
Los diagramas posteriores nacen del MMABP-IR validado, no de respuestas literales.
No cosmética de consistencia
Ante contradicción, no se alinean modelos por forma; se regresa a realidad factual.
No mezcla PM/PF
PM conserva intención global y sincronizaciones; PF conserva flujo detallado.
No OLC como proceso
OLC representa causalidad del objeto; no secuencia de tareas humanas.
